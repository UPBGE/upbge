Split-Screen Guide

How the Split-Screen FPS Example is made: two players in one window, each with their own view, HUD, minimap and menus (an inventory with equipment and crafting, a chest, settings), a pause menu for both, a computer one player takes over and a terminal everyone uses. Open it with Add › Game UI › Open Split-Screen Example and follow along: every logic frame of the example is pictured here with what it does.

1. Play the example

Add › Game UI › Open Split-Screen Example opens a new, unsaved copy of the example. Play it with Render tab › Game Resolution › Embedded Start (in the 3D view) or Standalone Start (its own window).

  • Player 0 (the object Player, left half) plays with the keyboard and mouse.
  • Player 1 (the object Player 1, right half) plays with the first gamepad: the scene's Gamepads Start at Player 1 is on. Without a gamepad player 1 stands still.
  • Walk to the chest, the computer (left) and the public terminal, pick items up, open the bag, eat, craft, equip, change the settings, pause.

Player numbers. The nodes count players from 0: User 0 is Player, 1 is Player 1. The texts on screen and a few frame titles count from 1: there “Player 1” means player 0 and “Player 2” player 1. This guide always counts from 0.

2. How it works

  1. One tree for every player. Player and Player 1 run the same logic tree, Game. Each has a game property user (its number); every node that acts for a player takes it as its User.
  2. A camera for each player splits the window. Set Camera with User 1 gives player 1 a view of their own; Set Split Screen lays the views out.
  3. Each player gets their own copy of a menu. Open Object Menu with a User and Area Player's View opens that player's copy, inside their view. The copy's logic runs for them: Get Menu Player gives its player and its owner (the player object), and widgets, texts and grids read the owner's properties.
  4. Each camera can draw something else. Set Camera Visibility hides a player's own body from their own camera; Set Camera Viewport draws a minimap camera inside a player's view.
  5. Input belongs to a player. Input Action reads an action of the Game Input Map for its User. Player 0 has the keyboard and the mouse; the gamepads go to the players after them. Players aim at buttons in the world with the middle of their view (Set Player Pointer View Center).

The UI in short

  • A menu (and the HUD) is a collection: here inside the collection UI, which is Disable in Viewports so its objects are not in the game world. Open Object Menu shows it through a camera of its own, InvCamera.
  • A UI Element is an object with Game Components tab › UI Element on: it takes clicks, focus and drags. On UI Event reports what happens to it, with its Action name.
  • Widgets (Slider, Toggle, Selector, Text Field, Bar) show and change a game property by themselves: the element's own or a parent's, else the menu owner's.
  • Live text: braces in a text show values and keys, and update by themselves: {player_name}, {Computer.message}, {Use}.
  • The menus here are built as in the UI Guide (Add › Game UI › Open UI Guide), which explains each piece step by step.

7. Map and minimap

The Map action cycles the player's map_mode: 0 shows a live minimap (a camera over the player), 1 a picture with dots, 2 nothing.

The minimap cameras are children of the players, 30 m above them, looking down, orthographic, drawn with Workbench (cheap: no lights, no shadows). Minimap 1's Viewport Shape is Circle: player 1's minimap is an oval filling the same rectangle as player 0's, to show both (Width and Height are parts of the view's width and height: in a tall half view the rectangle is taller than wide).

8. Items and pickups

An item is an object in the scene's Item Library (Scene tab › Items and UI): the collection ItemLibrary, inside the hidden UI. The object's name is the item's name; its game properties say how it shows and stacks (name, max_stack, category, description) and what it does here (restore: stamina when eaten; durability: fills the tooltip's “Durability {durability}”). The menus show its mesh as the item's icon. The durability bar on a cell reads the slot's own durability, a column of the list: only Player's inventory has it (its starting Sword at 60); added and crafted items get no value there, so their bar stays hidden.

18. Make your own

A split-screen game

  1. Make one player object with its logic tree, a game property user (Integer) and a camera (on a head empty, for looking up and down). Link user into every User input of the tree.
  2. Copy the player (with its children) for each other player and give each copy its user: 1, 2...
  3. When the game starts, Set Camera with each player's User and camera, then Set Split Screen.
  4. Scene tab › Game Input Map › Settings › Gamepads Start at Player 1 for a keyboard player and gamepad players; off, player 0 also has the first gamepad.
  5. Open menus with Open Object Menu, User the player, Area Player's View; in the menu's logic use Get Menu Player.
  6. Set Camera Visibility with Keep Shadow hides a first-person body from its own camera.

A third player in the example

  1. Select Player 1 with its children and copy them (Shift D): the copy's camera and head and its minimap's player already name the copies. Set the copy's user to 2, and the copied minimap camera's user to 2.
  2. Add a Set Camera with User 2 and the new camera to the Split Screen tree. Set Split Screen's 3 Players is Favor Top already.
  3. For the map picture, copy Map Dot 1 and set its track to the new player.
  4. The terminal's Open Together knows players 0 and 1 only (its Switch Flow cases).
  5. Player 2 plays with the second gamepad.
